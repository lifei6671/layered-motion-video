# 静态漫画视频自动合成引擎：分阶段实施清单

> 编制日期：2026-10-21。
> 依据：[静态漫画视频自动合成引擎 V2.0](./静态漫画视频自动合成引擎.md)。
> 当前状态：仅完成任务拆解；以下开发、依赖安装、渲染和验收均未执行，初始状态为 `NOT_RUN`。
> 已确认口径：语义优先，允许全片使用有充分叙事依据的硬切，不设置特效数量或种类配额。技术探针仍须覆盖全部首版效果。
> 图片供应：每期开始向用户确认本地生图、授权第三方检索、人工按提示词生图或混合模式；逐镜头图片需经人工确认才能进入正式渲染。

## 1. 范围与执行规则

### 1.1 本清单对应的产品

输入为已确认中文原文、完整配音和分镜；图片可由 Codex 调用已授权的本地生图工具、从有适当使用许可的第三方网站/图库检索下载，或由 Codex 交付提示词后用户自行生图并放入规定目录。支持逐镜头混合来源。Python 负责来源与审核管理、输入验证、语音辅助定时、人工覆盖及时间线编译；Remotion 负责整片无声视觉渲染；FFmpeg 负责母带、最终封装和媒体验证。

首版输出为 1920×1080、恒定 30 fps、H.264、AAC、`yuv420p` 的无字幕视频。支持整图静止、推近、拉远、水平/纵向平移，以及 `cut`、`fade`、`fade_black`、`wipe_from_left`、`wipe_from_right`。

本版包含**三种图片供应渠道的编排、调用/检索适配、提示词交付、素材溯源和人工审图**；不自研基础图像模型、通用爬虫平台或图库服务。其他范围不包含：字幕、TTS、背景音乐、人物口型、独立角色/道具动作、多轨道编辑、任意特效代码、FFmpeg 视觉滤镜后端、分段视频缓存和批量队列。原分层动画路线保持独立。

### 1.2 开发和验收约束

- 本文件不是立即开始编码的指令。后续启动开发时，按授权阶段执行，不自动扩大范围。
- 各阶段只交付本阶段及必要依赖；先通过关键探针，再扩展工作流。首版完成需通过 SC-P0～SC-P7，单个探针成功不能代表引擎完成。
- 转场候选必须参考真实原画、相邻旁白、当前运镜及停顿。程序执行受控数据，不能让 Agent 直接生成并执行 React、Shell 或任意脚本。
- 不以模型返回成功代替对齐成功，不以渲染成功代替人工接受，不以低清预览批准代替正式画质批准。
- 当前文档中的命令和未来目录均属于设计，不声称已存在。实施时按实际配置确定构建和测试命令。
- 保留已有 Git 修改；不因执行阶段而自动提交、推送、发布或修改另一条路线的文档。

### 1.3 每期项目的图片渠道确认与审核门禁

**开始先问：** 每次新建视频项目或接手尚未选定图片来源的项目，Codex 必须让用户选择：① `agent_generate`：使用已连接的本地图片生成工具；② `third_party_retrieve`：从允许检索及使用的第三方网站/图库获得图片；③ `manual_generate`：Codex 提供完整提示词，由用户手工生成并放入指定目录；④ `mixed`：按镜头混合前三者。无明确选择则保持 `SOURCE_POLICY_PENDING`，禁止自动生图、抓取和正式视觉渲染。已经确认且仍有效的渠道无需重复询问。

**混合模式：** 先根据已确认分镜建议每个镜头的 `source_mode` 和具体渠道；用户确认逐镜头来源分配后再执行。更换单镜头渠道、工具或第三方来源需用户再次确认。若选定工具不可用，报告 `UNAVAILABLE` 而非静默换渠道。

**统一人工审图：** 本地生图和第三方图片必须由用户审核最终效果；人工供图放入目录后还需技术检查，并由用户明确确认采用。支持逐图或明确指定批次批准。审核绑定镜头、源渠道、图片内容哈希及批准人；候选文件与文件存在均不等于批准，已批准图片发生变化则旧批准失效。

**第三方来源权利：** 优先使用站点许可的图库接口或符合其服务条款的访问方式，遵守许可、署名和访问限制。保存原始网址、作者/机构、许可证明、访问日期、下载方式、署名要求及哈希。缺少传播/发布使用权依据时进入 `REVIEW_REQUIRED`；用户对审美的批准不代表授权已经取得。只供参考的第三方图应标记 `reference_only`，不得直接混入成片，派生创作须审查相应许可。

### 1.4 每阶段统一完成记录

各阶段保留一条可追溯的执行记录，至少包括：阶段及任务 ID、输入/代码版本、交付路径、实际命令、验证结果、失败或未执行原因、人工审核结论、剩余阻塞项。利用已有报告文件记录，不另建任务管理系统。

状态统一使用 `PASS`、`FAIL`、`NOT_RUN`、`UNAVAILABLE`。没有实际执行证据不得勾选任务。需要人工接受的条目，必须在收据中记录真实批准人及对应产物摘要；Agent 不能代批。

**停止条件：** 环境和版本基线稳定后进入 SC-P1，不提前搭建队列、插件系统或跨平台安装器。

## 4. SC-P1：输入契约、时钟与图片快照

**范围：** 建立唯一的数据契约、图片来源策略与审核状态协议，以及确定性时间线。使用已知时间与测试图片夹具，本阶段不进行真实批量生图或检索。

### 任务

- [ ] SC-P1-01：定义分镜、人工覆盖、时间线和 props 的 Schema；Python/TypeScript 使用同一契约来源，避免独立维护不一致枚举。
- [ ] SC-P1-02：实现项目输入校验，保留原始字节和 Unicode 码点偏移；覆盖 BOM、CR/LF、重复句及非 BMP 字符，JS 不得把 UTF-16 code unit 当作原文码点。
- [ ] SC-P1-03：实现 V2.0 受控相对路径规则，校验解析后的文件/目录归属；拒绝绝对路径、盘符、UNC、穿越、越界符号链接/联接点及不合法输出位置。
- [ ] SC-P1-04：用整数采样和整数帧计算 T、绝对边界和镜头逻辑长度。首版只接受 30 fps，模型原始秒数只留作证据，不重复取整。
- [ ] SC-P1-05：编译三种 placement、前后保持帧、物理长度和窗口；检查覆盖完整、窗口不越界、不互相侵入，且每镜头至少保留一帧非转场状态。
- [ ] SC-P1-06：实现方向/色彩/画幅预处理、cover 审核预览、主体框坐标变换和逐帧裁切计算。
- [ ] SC-P1-07：仅允许有效人工批准的正式图片进入项目级 public 目录，以内容哈希命名并复核暂存哈希；技术测试图片单独标注为夹具，不得误认为正式已审素材。
- [ ] SC-P1-08：新增 `input/image_source_policy.json` 的 Schema，含单一/混合模式、用户确认、允许渠道与用户更改来源审批；未确认时维持 `SOURCE_POLICY_PENDING`，禁止执行图像获取。
- [ ] SC-P1-09：定义 `assets/images/manifest.json` 的逐镜头资产 Schema，记录来源、用途、提示词/检索条件、作者、第三方许可、源地址、样式版本、文件哈希、审核状态与审核人。
- [ ] SC-P1-10：定义候选图片与人工放图路径、文件命名和自动检查：`work/images/candidates/` 暂存候选，`assets/images/shot_XXXX.png` 为正式目标路径；手动放图仍需人工确认。

### 交付物

- Schema 与有效/无效输入夹具。
- `timeline.lock.json`、`props.json`、`staging-manifest.json` 及不可变图片快照。
- 图片渠道策略、逐镜头资产清单和批准收据的 Schema/夹具（`image_source_policy.json`、`manifest.json`、`review/image_approvals.json`）。
- 编译器、输入边界和几何测试结果；非 16:9 素材的可审查裁切预览。

### 验收标准

1. 相同输入与版本得到相同时间线；异常范围、非法引用、未知动作/转场和非 30 fps 配置明确失败。
2. 全局边界取整无累计漂移；`sum(logical_frames)=T`，`sum(physical_frames)-sum(transition_frames)=T`。
3. `120/150/90` 逻辑帧、12 帧 `end_at_anchor` 加 12 帧 `start_at_anchor` 得到物理长度 `120/174/90`、窗口 `[108,120)` 和 `[270,282)`、总计 360 帧。
4. 三种 placement 覆盖奇数/偶数持续帧数；超短镜头、相邻窗口冲突、首尾越界均定位具体边界，不自动缩短效果。
5. 素材目录只公开图片，不含旁白、原文或审核文件；修改原图不会隐式改变已暂存快照。
6. 主体逐帧裁切结果可定位；未标注主体报告未验证。比例不符的输入不被浏览器擅自裁切或拉伸。
7. 未确认图片渠道、混合模式未确认逐镜头来源、候选图未审或第三方授权证据缺失时，生产素材晋级和正式视觉执行必须被阻断。
8. 手动供图即使已按规则放进 `assets/images/`，在用户明确批准前仍为 `REVIEW_REQUIRED`；已批准图片被替换时，内容哈希与审核收据不再匹配。

**停止条件：** 契约与数学验证通过后进入真实视觉探针；此阶段不宣称视频已正确渲染。

## 5. SC-P2：Remotion 运镜与转场技术探针

**范围：** 只验证静态图片的确定性视觉执行层，所有画面由 Remotion 生成，不使用 FFmpeg 运镜或转场滤镜。

### 任务

- [ ] SC-P2-01：建立最小 `StaticShot`、`ComicVideo`、Root/Composition；由 `calculateMetadata` 读取锁定 T、画幅和 30 fps。
- [ ] SC-P2-02：实现 smoothstep、局部缩放和裁切锚点；局部帧扣除 head hold 后 clamp，保持阶段不得推进运镜。
- [ ] SC-P2-03：以 `TransitionSeries` 实现硬切、fade 和两个方向的 wipe；硬切不插入零帧 Transition。
- [ ] SC-P2-04：实现受控 `fade_black` presentation 和固定黑底，验证确实经过黑色，不以普通 fade 冒充。
- [ ] SC-P2-05：验证 `start_at_anchor`、`end_at_anchor`、`center_on_anchor`，覆盖混合序列、连续转场和全硬切技术夹具。
- [ ] SC-P2-06：从锁定 props/public 快照打开 Studio，并导出无声 H.264 视觉轨；验证本地 CLI、参数文件、`--public-dir` 及 `--muted` 的实际行为。

### 交付物

- 最小可运行 Remotion 视觉模块与受控转场组件。
- 单图运动、五类转场及三种位置的技术短片、逐帧截图和期望值对照。
- 360 帧预算探针与 ffprobe/完整解码结果。

### 验收标准

1. 静止、推近、拉远、横移、纵移的起止构图与预期一致；单帧镜头和保持帧行为正确，不依赖随机数或墙上时钟。
2. SC-P1 的 360 帧夹具实际输出恰好 360 帧；第一处在全局第 120 帧完成切换，第二处在第 270 帧开始；第二镜头正常运镜从第 120 帧开始。
3. 转场开始、结束附近逐帧检查，不只看容器长度；前后保持不改变逻辑运动速度，擦除实际方向符合枚举含义。
4. 淡黑按约定经过黑色且不额外增加时长；奇数/偶数时长均检查实际离散采样状态，出现端点差异须修正或明确合法参数限制后再放行。
5. `visual.mp4` 无音轨，实际帧数、分辨率、像素格式、SAR 和恒定帧率正确，PTS 连续且无意外黑帧。
6. Studio 和导出使用同一输入快照；至少一次在 1080p 下查看高对比漫画细线，记录闪烁、软化等问题。

**停止条件：** 视觉关键风险验证通过再扩展生产工作流；旧 FFmpeg 实验不能替代本阶段证据。

- [ ] SC-P3-06：输出可定位异常和确认边界，接回 SC-P1 编译器；真实漏读不能靠移动镜头边界消除。

### 交付物

- `master_48k.wav`、`align_16k.wav`、粗识别记录、`aligned.json` 和异常报告。

- 正常中文配音和漏读/截断反例的验证记录。

### 验收标准

1. 真实配音包含数字、百分比、术语、缩写和重复短句，人工检查每个候选边界；所有待执行边界有可信证据或明确人工确认。
2. `28%` 等一对多读法能回溯原文，不把数字字符数量当作发音数量；相同短句不串位。
3. 模型回退、插值、缺失时间不会误标为精确成功；匹配率仅预警，不单独决定放行。
4. 漏读、加读或截断产生原文区间、采样位置和镜头定位，并阻止错误放行。
5. 合法人工修正可恢复编译；旧摘要、冲突覆盖、越界时间被拒绝；相同覆盖可重复应用。
6. 16 kHz 与 48 kHz 时间转换无重复偏移或混用采样单位；母带与源配音内容、速度和停顿一致。

**停止条件：** 已确认镜头边界足以制作样片即进入 SC-P4，不为内部少量无关字符无限追求精度或新增自动后端切换。

**范围：** 只读取 SC-P3A 已经取得有效人工批准、来源与图片哈希可核验的真实原画；将相邻旁白、运镜与停顿转为可审核的转场候选。候选和执行数据分离。

### 验收矩阵

| 变更/故障 | 正确行为 |
|---|---|
| 完全相同输入重跑 | 复用通过检查的同版本阶段产物 |
| 替换一张原画 | 新图先返回待审核，批准后重新预处理相关图并重渲染整片视觉轨，相关转场和预览批准失效 |
| 混合模式中单镜头切换渠道 | 用户确认后重做此镜头来源分配与候选，图片批准、转场视觉证据、相关预览审核失效 |
| 第三方许可或来源信息变化 | 即使图像字节相同也须复核相关许可，不得自动复用原有授权批准 |
| 手动供图出现、覆盖或缺失 | 以实际文件哈希检测；放入目标命名路径仍为待审核，缺失时不得放行 |
| 改运镜、转场类型/位置/时长 | 重编译并整片视觉重渲染，重新审核 |
| 仅改转场解释，执行画面不变 | 可复用相同视觉内容，但语义批准失效 |
| 仅改配音且重新核对后视觉时间线确实不变 | 重做音频相关阶段和封装，可复用视觉轨，重新有声审核 |
| 配音使 T 或边界变化 | 重编译、整片视觉重渲染、重新封装和审核 |
| 删除/损坏视觉轨或命中键不符 | 不命中缓存，重新生成并验证 |
| 渲染/封装失败、缺图或暂存哈希不符 | 明确失败，不更新批准，不覆盖有效旧成片或把旧文件报告为新结果 |

**停止条件：** 矩阵通过后进入真实样片，不把“改一张图只重渲染一个镜头”加入首版验收，也不提前开发区间拼接。

### 验收标准

1. SC-P0～SC-P6 的必要契约通过，真实样片视频帧数严格为 T，音轨完整，首版全部功能可用。
2. 人工确认换图和转场服务于叙事，关键观点出现时画面处于预期状态；全片合理硬切可通过。
3. 完整观看 1080p 视频，关键主体无误裁，慢推细线无不可接受闪烁/软化，转场不遮蔽核心信息；问题需修复后重审。
4. 全片试听确认配音无吞字、错位或被截断，不能用自动时长检查替代试听。
5. 所有阻塞异常解决并有证据；未执行或环境不可用的项目如实标记，阻塞验收时不能宣称首版完成。
6. 性能与人工工作量有实测记录；未预设渲染速度 SLA，不凭主观估计宣称可实时或适合大规模批量。
7. 每张入镜图片均有可追溯渠道、提示词/检索记录、原始来源、权利证据、人工批准及哈希；驳回图不得出现在输出。

**完成门槛：** 技术检查、语义审核、完整试听、正式画质四项均通过，且必要阶段无阻塞剩余。完成的是静态漫画合成首版，不是原分层动画路线，也不包含上线发布。
