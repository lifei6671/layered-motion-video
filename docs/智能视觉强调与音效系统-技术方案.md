## 1. 产品目标与关键约束

### 1.1 要实现什么

在用户已经批准的静态漫画镜头之上，自主决定**是否**添加强调文字；当需要时，根据旁白语义、真实漫画构图、主体位置、镜头运动及上下文情绪，选择文字内容、出现位置、表现方式、复杂程度与持续时间。同时，为**全片**规划可选音效：包括关键词、场景、转场与叙事强调，且允许任意镜头完全静音（旁白照常播放）。

核心不是“每个关键词都动起来”，而是：“语义重要性 × 当前画面可承载性 × 叙事节奏 × 声音必要性”的联合规划。文字和音效分别有独立的 `skip` 决策，彼此不强制绑定。

### 1.2 已明确的业务事实

- 漫画画面主要是不可控的**单张扁平静态图片**，可以运镜，但当前不具备角色、背景的稳定深度分层；文字只作为上层叠加，**不承诺与人物物理互动或被人物遮挡**。
- 智能混合模式：Agent/规则给出候选，用户可以修改、固定、排除。自动分析的结果是提议，实际渲染只消费经过结构化校验和锁定的配置。
- 不是所有主题、镜头都适合文字。无文字、无音效均属于一等合法结果；需有可解释的跳过原因。
- 动画可以使用常规文字动效、高级二维特效、受限的预渲染透明特效；复杂度应该受设备和缓存预算控制。
- 全片音效由 FFmpeg 与完整旁白混合；原始音频母带始终保留，不在原始旁白上直接修改或覆写。
- 当前项目已有图片来源、逐图审图、语音、语义转场、有声预览和正式画质审核门禁；本扩展必须继承。

### 1.4 常见失败模式

1. 让模型根据原图直接算出唯一文字位置，但忽略镜头推近、平移和文字放大的极值，导致播放时遮挡主体。
2. 以“全自动关键词提取”为目标，忽略“该镜头不应有文字/音效”的判断，使每个画面都像短视频贴纸广告。
3. 把文字放入 `StaticShot`，用局部帧驱动；当前 `TransitionSeries` 含镜头保持帧和重叠窗口，会导致时间偏移和跨镜头重复。
4. 直接把音效与旁白混在原始 WAV 中，既破坏原始证据，也让音效变化触发不必要的视觉重渲染。
5. 用默认 `amix` 归一化处理而忽略旁白增益变化；或用 `-shortest` 掩盖音效越界、母带损失。

## 2. 总体架构与“决策—编译—执行”分离

```text
原文 + 已批准分镜 + 原始旁白 + 已批准漫画图
                  │
          现有 SC-P3 声学对齐
                  │
          镜头几何、运镜关键帧
                  │
       ┌──────────┴───────────┐
       ▼                      ▼
视觉理解与强调规划         全片音效候选规划
(每镜头可 skip)           (每镜头可 silence)
       │                      │
       └──────────┬───────────┘
                  ▼
      候选 JSON + 人工覆盖计划
                  │
                  ▼
       受控编译器/校验器
       ├─ 原文索引→声学样本→绝对帧
       ├─ 图像帧采样→位置碰撞→视觉事件
       ├─ 声学/镜头/转场锚点→音效采样事件
       └─ 字体/特效/音效来源、许可、哈希校验
                  │
        ┌─────────┴──────────┐
        ▼                    ▼
  Remotion 无声视频轨    FFmpeg PCM 音效混音轨
 (漫画+文字+特效)       (完整旁白+可选效果)
        │                    │
        └─────────┬──────────┘
                  ▼
     FFmpeg 合成有声预览 → 用户完整试听审核
                  │
                  ▼
       正式视频封装与可追溯验证
```

**唯一权威时钟**为 48,000 采样/秒和 30 帧/秒。Python 负责编译与冻结事件；Remotion 只使用锁定的绝对帧执行视觉；FFmpeg 只根据锁定的整数采样时刻做混音。模型不能输出可执行脚本、任意滤镜字符串、自由 CSS 或任意网络素材地址。

## 3. 两层智能决策：先判断要不要，再判断如何呈现

### 3.1 镜头级决策状态

对每个 `shot_id` 生成独立的两个决策：

- `text_decision`: `auto | show | skip`；`auto` 由编译前的视觉规划确定，`show` 表示人工确认允许使用、并非强制每帧都展示；`skip` 表示本镜头不生成任何文字事件。
- `sfx_decision`: `auto | allow | silence`；`silence` 表示本镜头的逻辑展示窗口不允许出现新增音效（包括从前一镜头延伸而来的音效尾巴），**仍正常保留旁白**。需要跨边界衰减时，应在编译前调整音效长度或明确取消该镜头的 `silence` 决定。即使无文字也可独立选择转场或叙事音效。

最终决策必须携带 `reason_code`、中文简述、相关原文范围及观察证据；`skip/silence` 不是错误。人工 `skip/silence` 优先于所有模型候选。

### 3.2 视觉分析必须使用最终会被渲染的画面

1. 检索当前已获准图片的**规范化快照**，不是未审候选图、第三方缩略图或旧画面。
2. 通过现有运镜函数和 `geometry.json`，至少抽取镜头开始、1/4、1/2、3/4、结尾以及关键词候选时间点的图像帧；对平移、放大极值增加抽样。
3. 视觉模型可提供：重要主体区域、嵌入文字/数字区域、相对留白、背景复杂度、对比度、叙事情绪、各候选区域的可用性、是否适合文字及说明。必须标注这是**视觉建议**，而不是可信碰撞证明。
4. 确定性排版器在全片运动采样帧中计算文字的**最大运动外接框**（包括回弹超调、描边、阴影、粒子区域），与安全边界、主体框、内嵌文字区、屏幕边缘比对。
5. 如果缺少可信主体框，给出 `UNVERIFIED`；若视觉拥挤、无安全位置、长文本无法容纳、情绪不适合或语义价值低，自动 `skip` 并记录原因。人工可通过明确布局覆盖，但仍须经过可读性、安全区和预览审核。
6. 任意自动模型结论都不能直接写入生产 `props.json`；先经合约和确定性编译器校验并锁定。

建议跳过原因枚举：`VISUAL_BUSY`、`EMBEDDED_TEXT`、`NO_SAFE_REGION`、`LOW_SEMANTIC_VALUE`、`QUIET_NARRATIVE`、`SCENE_MOTION_CONFLICT`、`TIMING_UNCERTAIN`、`DENSITY_BUDGET`、`MANUAL_SKIP`。候选失败时保留具体证据与帧号，不能默默放到画面正中央。

### 3.3 语义选择与场景节奏

`concept`（术语）、`number`（关键金额/比例）、`contrast`（对照）、`impact`（反转）、`sequence`（步骤）优先成为文字候选。视觉富集场景、情绪克制的叙事和强转场附近应降密度。不要机械地为每段旁白提取关键词；整镜头可以得到零个文字事件。

默认预算（均为可配置的候选策略，而非普遍标准）：文字每分钟最多 8 个、每镜头最多 3 个、同屏最多 1 个、事件间最少 12 帧；高强度爆字同镜头原则上不超过 1 次。音效独立预算，默认每分钟最多 10 次、同时最多 2 路短音效，并允许完全不使用。

### 4.4 编译后事件：统一时间、分离执行

**视觉事件**写入 `work/emphasis/visual.lock.json`，包含 `id`、`shot_id`、`script_range`、`speech_samples`、`anchor_frame`、`start_frame`、`end_frame`（排他）、`enter_frames`、`hold_frames`、`exit_frames`、`preset`、`tier`、`layout`、`font_asset_id`、布局风险和输入哈希。全片播放区间必须处于 `[0, total_frames)`，严格使用现有 `frame_at` 和 `compile_timing`。键顺序和输出字节要可复现。

**音效事件**写入 `work/emphasis/sfx.lock.json`，包含 `id`、`kind`、`asset_id`、`asset_sha256`、`anchor_origin`、`start_sample`、`source_trim_samples`、`play_samples`、`gain_db`、`fade_in_samples`、`fade_out_samples`、`mix_bus`、`status` 和输入摘要。所有整数样本以全局母带 48 kHz 为准，限制 `0 <= start_sample` 且 `start_sample + play_samples <= mother_samples`。

视觉精度为一帧粒度，音效可在样本粒度定位。**同步规则**：与文字冲击点绑定的音效，默认 `start_sample = anchor_frame × 1600 + offset_samples`；与念词发音直接绑定的音效，默认来自实际声学 `start_samples`。二者最多存在 half-up 造成的半帧量化差，不能用反复秒转帧补偿。任何自动延迟/提前量都必须落入事件锁文件并可解释。

### 4.5 契约迁移策略

- 原有 `props.schema_version=2.0` 通过增加**可选** `visual_emphasis` 字段扩展，旧 props 继续有效；不要偷偷改动已有 shots、transition 的定义。
- 新增 `$defs`：`emphasisPolicy`、`emphasisPlan`、`shotEmphasisDecision`、`visualEmphasisEvent`、`sfxEvent`、`fontManifest`、`sfxManifest`、`compiledVisualEmphasis`、`compiledSfxEvent`。
- `contracts.generated.ts` 必须由现有生成流程更新，两端校验同一有效/无效测试样本。拒绝重复 JSON 键、未知字段、`NaN`、越界时间、非法目录、任意代码和 URL。
- 视觉 props **不包含音效 PCM 或音效事件本身**，避免仅修改声音就改变视觉轨缓存键。音效与混音所需哈希独立参与整部有声预览/正式交付快照。

## 5. 文字选词、声学对齐、转场与位置规划

### 5.1 精确的原文与声音对应

1. 对 `input/script.txt` 做已有 UTF-8 BOM/Unicode 码点处理，逐字校验 `script_range`；若两个同名词分别出现，不能使用第一次 `find()` 来定位。
2. 经现有 `speech.apply_alignment()` 重放完整语音证据，读取 `reading_map.source_ranges` 及字符级 `characters`。源文字数字/金额可能映射到多个读法字符，必须全部消费该范围；低分数、缺失、插值、粗段回退不能伪装成精确词级时间。
3. 可验证的字符首尾样本构成真实声学窗口。`anchor_frame=frame_at(first_sample)`。动效视觉峰值对应这个绝对帧，入场可以提前数帧；完整显示时长需覆盖词语的核心发声窗口。
4. 进入、停留、退出是**绝对帧的子区间**，必须适配已编译镜头的非转场稳定窗口；自动候选空间或时间不够时跳过，人工固定项冲突返回 `REVIEW_REQUIRED`。
5. 发生词句变化、音频变化、读法覆盖变化后，自动使旧视觉与音效计划的锁定数据失效，重新走当前审核。

### 5.2 位置与表现形式

确定性规划器参考多帧图像观测，在安全边距内对 `upper_left`、`upper_right`、`left_center`、`right_center`、`lower_side` 等布局候选打分，综合留白、显著主体距离、背景明暗对比、阅读方向、已嵌入文字及运镜动态；模板和字号也参与占位模拟。无法证明可用就 `SKIPPED` 或 `UNVERIFIED`，不能强行将文字置于中央。

视觉模型可帮助提取多物体框和嵌入文字区；现有 `subject_bbox` 只覆盖已标记的主体，不能声称自动发现所有人物、道具或文字。涉及审美与画面拥挤度的最终审核仍依靠真实有声视频。

### 5.3 文字与镜头风格适配

提供白名单视觉主题，如 `comic_bright`（明亮漫画）、`comic_ink`（墨线漫画）、`minimal`（知识图解）、`cinematic`（克制叙事）。字体、色彩、描边、阴影、装饰线、抖动幅度及配套音效由主题选择，不直接让 Agent 提供任意 HTML/CSS/React/滤镜命令。若主题不适合强特效，降低层级或选择零文字。

## 6. Remotion 视觉轨与三级动画复杂度

### 6.1 放置位置与统一帧语义

在 `ComicVideo.tsx` 中将 `<VisualEmphasisOverlay />` 放在 `<TransitionSeries>` **后面作为兄弟层**，而不是塞入 `StaticShot`。每个视觉事件使用 `<Sequence from={start_frame} durationInFrames={end_frame-start_frame}>`；局部 `useCurrentFrame()` 只负责计算这个事件在当前窗口的运动状态。文本动画由 `spring()`、`interpolate()`、SVG 路径和确定性计算产生，禁止基于墙上时间、浏览器 CSS 过渡或未经锁定的随机数。

关键节点（如 `enter_start`、`impact`、`settle`、`exit_start`）应由模板统一暴露，供可选音效事件引用。锚点统一写入编译锁文件，避免两个模块各自重新计算效果峰值。

### 6.2 一级：常规漫画文字动画（首批必做）

| 模板标识 | 动画说明 | 默认音效建议 |
| --- | --- | --- |
| `soft_rise` | 淡入、轻上浮、淡出 | 默认静音 |
| `comic_pop` | 放大、轻微超过目标比例、回弹 | 可选轻弹跳声 |
| `comic_burst` | 粗描边、放射线、冲击放大、短震动 | 可选短冲击声 |
| `number_tick` | 数字变化并精确停止在源文案的真实值 | 可选短计数提示声 |
| `underline_reveal` | 术语出现、底部强调线展开 | 默认静音 |
| `stagger_group` | 多个有源文案依据的概念依次排列 | 默认静音或极轻声 |

样式选择与配音效选择分开；有文字不意味着一定播放任何声音。

### 6.3 二级：高级二维文字特效（受预算控制）

实现独立模板，如 `ink_reveal`（水墨揭示）、`light_sweep`（光线扫字）、`fragment_disperse`（字形碎片散开）、`particle_assemble`（粒子聚字）。优先用 SVG/画布绘制、固定字形遮罩和离线预计算的粒子运动数组；所有随机参数以计划事件 ID + 资产 SHA256 派生的固定种子生成并锁定，不在每帧重新随机。

每个模板应定义像素最大外接框、最大粒子数、最大帧数、最高显存/内存预算和低配回退模板。例如首版建议粒子数不超过 120、动画时长不超过 90 帧；数值须在真实机器基准测试后再调。二级模板可以禁用，计划器应自动选择可用的一级模板并记录原因。

### 6.4 三级：预渲染透明复杂特效（按需启用）

三维材质、复杂破碎、体积光等先通过单独的受控模板生成透明 PNG 序列或含 alpha 的透明视频（例如经验证的 WebM/ProRes 工作流），再由 Remotion 根据绝对帧播放。预渲染的输入必须明确：原文、已授权字体、模板版本、尺寸、分辨率、帧率、透明格式、种子与源模型/工具版本，输出必须记录逐文件或整资产摘要。

生成后须验证透明边缘、帧数、alpha、色彩、质量、跨设备兼容性以及透明合成时的性能。含 alpha 视频必须验证当前**锁定**的 Remotion 4.0.515 和浏览器/FFmpeg 能否按预期解码；不根据最新版文档推断本机已经拥有全部能力。失败时明确选择一级/二级回退并重新预览，不静默丢掉特效。默认不要为每个视频引入高级三维引擎、独立素材下载和 GPU 重渲染义务。

## 7. 全片音效：场景、转场、叙事与关键词

### 7.1 音效来源与授权

建立受控音效库。每个条目有 `asset_id`、相对资源路径、原始 SHA256、规范化 PCM SHA256、来源种类（本地制作/用户提供/授权第三方/人工确认的生成工具）、作者/许可/使用范围、采样率/通道/持续样本、类别标签、审核状态。

音效来源可像图片一样混合选择，但**只有已授权且来源/权利可核验的资源才允许进入正式视频**。新下载或新生成的音效应先进入候选目录；已获长期授权的可复用资源无需每期逐个重复审批，但应在本期预览中获得听感确认。禁止仅凭描述或文件名宣称音效已获取或有版权。

### 7.2 音效类型与智能策略

| 类型 | 例子 | 触发条件 | 默认策略 |
| --- | --- | --- | --- |
| `keyword` | 轻弹、冲击、数字定格 | 指向实际存在的视觉动画关键节点 | 与文字分开判断，通常少量使用 |
| `scene` | 纸张翻动、提示音、物件落下 | 场景语义和镜头画面有明确依据 | 静止漫画只建议风格化提示音；不凭空制造物理动作 |
| `transition` | 轻风声、翻页声、淡化提示音 | 使用已批准的转场类型和真实转场窗口 | 非所有转场必须配声，`cut` 可完全静音 |
| `narrative` | 发现真相、反转、悬念提示 | 源文案语义锚点、真实对齐证据 | 克制使用，避免干扰口播 |

对于严肃、沉思、情绪克制的镜头，应倾向 `silence`。转场或画面没有实际动作时，不能仅凭一张静态“爆炸场景”图片就推断发生真实爆炸，并加入巨大爆炸声；这里优先使用非写实的叙事音效。

### 7.3 时间轴与同步

- 音效时间始终是**全片绝对整数采样**，输入音效统一解码并规范化为 48 kHz、立体声 PCM。素材原始样本数、规范化样本数和任何重采样误差均需记录。
- 视觉冲击音：引用真实视觉事件的 `impact_frame`，换算 `start_sample=impact_frame*1600+offset_samples`。
- 旁白关键概念提示音：基于 WhisperX 通过验证的 `reading_map.source_ranges`、字符时间样本定位。
- 转场声：使用编译得到的 `transition_start_frame` / `transition_end_frame`，根据白名单 `start|mid|end` 和偏移推算采样，不再用文字猜测时间。
- 叙事声：使用已确认的原文区间 `speech_start`，或明确的镜头起点 `shot_start`。
- 源音效无时间证据、越界、跨越视频结束后才触发，自动候选应 `SKIPPED`；用户固定时明确返回 `REVIEW_REQUIRED`。
- 同一时段音效过密时，可按故事优先级降低增益、抑制部分候选或重新安排，但不能擅自挪动人工固定事件的关键音画同步点。还需对 `sfx_decision=silence` 的逻辑镜头窗口做样本区间碰撞检查：包含前一个镜头的音效尾部在内，任何音效事件都不能侵入该区间；可以在有依据的边界前淡出，无法无损调整的固定音效则进入人工待审。

### 7.4 FFmpeg 混音流程（双母带、单成片音轨）

1. 读取并验证 `work/audio/master_48k.wav`，获取真实 PCM 样本数 `S`。不能覆写此文件。
2. 音效库素材标准化为已校验的 WAV/PCM 48kHz 双声道，记录来源、哈希、音频峰值、时长。可单独通过 FFmpeg 执行，不需要触碰 Remotion。
3. 对每个音效应用受控的片段截取、增益、淡入/淡出、声像（可选），然后按 `start_sample` 使用 `adelay=...S` 进行样本级延迟（`S` 后缀代表样本单位）。拒绝负值、非有限值和异常大的延迟。
4. 将所有音效汇入 `sfx_stem_48k.wav`，控制并发和峰值。混音时以旁白为主：`amix=...:duration=first:normalize=0` 可以保持明确的输入增益控制，但仍需独立测量混合峰值及限制削波。切勿使用 `-shortest`。音效增益应受来源响度和业务类别限制。
5. 如需动态压低伴随音效，只对**音效轨**进行旁白驱动的侧链压缩/包络调整，不能把旁白本身压低来突出音效。`alimiter` 具有前瞻延迟，若使用必须计入延迟补偿并通过脉冲同步测试。响度标准化如采用 `loudnorm` 也要显式固定 48 kHz 输出并保留诊断。
6. 严格产出长度为 `S` 个采样的 `mix_48k.wav`，验证旁白样本从头到尾存在；音效若超出结尾，默认拒绝，只有在计划明确允许且有平滑淡出后才可截断音效分量，**不许截断旁白**。
7. 现有无声视觉轨继续由 Remotion 制作；`mux` 用混合音频母带编码成**一条 AAC 音轨**，H.264 视觉流复制，不增加第二条音频轨或额外字幕流。

FFmpeg 官方滤镜支持 `adelay` 的 `S` 样本单位、`amix` 的 `duration=first` 和显式 `normalize`，也支持侧链压缩；具体命令应由可信参数构造器生成，不接收模型生成的滤镜命令字符串。官方参考：https://ffmpeg.org/ffmpeg-filters.html 。

### 7.5 音频验收的必要改造

当前 `verify_media` 和封装路径以“完整旁白母带”为音频内容参考。引入音效后**不能继续将最终 AAC 解码结果直接与未经混音的旁白做字节级对比**；同时也不能删掉母带完整性校验。

建议验证分成四层：

1. 原始 `master_48k.wav` 文件哈希、真实样本数、起止内容维持现有验证。
2. 输入混音的 narration stem 与原始母带在受控解码/增益条件下一致，混音日志完整记录所有 SFX 资源、增益、时间、声音处理顺序。
3. `sfx_stem_48k.wav` 的预期非静音窗口与锁定事件一致；`mix_48k.wav` 长度严格为 `S`，采样率/通道固定，峰值、削波、响度和效果事件窗口可测。
4. 最终 MP4 解码后的单 AAC 音轨与**当前混合母带**做容忍有损编码、首包跳样本和末尾填充的内容核验；视频全帧一致性、零起点、帧率、时长与原先一样检查。实际听感、旁白可懂度和音效恰当性由真人完整观看试听确认。

## 8. 权限、质量与“允许不出现”的规则

- 自动规划的 `text_decision=skip` 和 `sfx_decision=silence` 必须有明确代码/说明，不构成生产失败；人工固定内容不可被隐式压制，冲突时进入 `REVIEW_REQUIRED`。
- 若 Agent 视觉模型不可用，应输出 `UNAVAILABLE` 并允许在用户已明确选择的规则/人工路径继续；不能伪造已看图的主体识别结果。无可信图像观察时可以保守跳过文字或请求人工布局。
- 字体与高级特效资源进入受控 `public/fonts`、`public/effects`，并计入 staging manifest、缓存和审批快照；音效不需要进入 Remotion public，不开放任意路径及外部 URL。
- 对中文字体覆盖率、超长文本、描边边缘、背景对比度、动态包围盒、主体碰撞、转场边界和粒子峰值进行程序检查；无法程序确定的视觉美感标记 `UNVERIFIED` 并需要用户预览确认。
- 音效资产需要来源和许可、文件摘要、技术格式审查。音效响度与旁白关系应在完整有声预览中人工审核，尤其避免突然刺耳、爆音、过量冲击声。
- 智能提议只能产生 JSON 数据，不得产生可执行代码。路径继续复用现有 `resolve_path`/签名/原子发布约束。
- 技术夹具可验证功能，却不能被当成实际生产素材或真人用户审批。用户原有图片渠道选择/逐图审查、转场确认、试听预览、正式画质批准全部沿用。

## 9. 缓存、依赖失效和审批绑定

将生产构建拆成彼此独立的可缓存节点：

| 输入变化 | 需要重新构建 | 可继续复用 |
| --- | --- | --- |
| 仅修改音效选择/增益/位置 | `sfx.lock`、SFX stem、混合母带、有声预览与最终封装、审核 | 已锁定图片、声学对齐、无声视觉渲染 |
| 仅修改文字内容/布局/模板 | `visual.lock`、Remotion props/视觉渲染、有声预览、最终视频审核 | 完整旁白、已批准原始音效文件；若音效不关联视觉节点，可复用原先 SFX stem |
| 修改声学对齐/旁白 | 有关视觉/音效时序、混音、预览/正式交付 | 已确认且未变更的图片资产与字体 |
| 修改分镜运镜/转场 | 视觉位置/时间、转场音效锚点、Remotion 轨与受影响审核 | 未改变的旁白与音效原始库文件 |
| 修改音效文件或许可 | 本期 SFX stem、混合母带、封装和预览审核 | 无声视觉轨 |
| 修改字体或文字特效源代码 | 视觉资源与渲染缓存、有声预览和最终审核 | 原始旁白、未关联文字锚点的音效 PCM |
| 扩展未启用/无视觉无音效 | 继续旧版编译、旧版有声封装语义 | 原有全部业务行为（源码变动引起正常构建缓存换代） |

**重要边界**：`delivery.snapshot()` 的全片审批指纹可以包含视觉与音效总摘要，但单独的 `visual_product` 构建键必须只包含视觉依赖，`mix_product` 构建键只包含声学与音效依赖。否则一改音效就会重新跑 Remotion，失去拆分缓存价值。

每次 `preview`、`render-visual`、`mux`、`verify` 重新校验当前音效计划、字形/特效、声学证据和资源许可。新增 `preview/emphasis_sheet.jpg`、`reports/mix.json` 进入当前预览/审核证据。修改任意影响成片的字段后，旧预览批准自动过期；正式质量审核仍为独立门禁。

## 11. 关键验收条件

### 11.1 功能验收

1. 对图文拥挤的镜头自动不生成文字；对情绪克制镜头允许无文字无音效；两个独立决定的 `reason_code` 可查询。
2. 在有足够留白的漫画镜头，关键词根据已批准画面多个运动采样帧合理定位；动态文字极值不会超出安全区或遮挡已标注的主体框。
3. 文本与已验证的原文码点区间精确一致，重复词、百分数读法、BOM、表情符号、跨镜头和低分数字符全部正确处理。
4. 一级六类动效正确出现；至少两种二级特效有真实逐帧视频验证。三级透明特效为可选扩展，需额外可用性与性能证明。
5. 音效能独立绑定 `keyword`、`scene`、`transition`、`narrative` 四类事件；每类至少有一个有效技术样例，同时允许零音效。
6. 音效入场样本、视觉冲击帧和已批准旁白起音的映射误差来自唯一可重算时钟，不存在镜头相对时间误差。对齐可疑时自动跳过或待审。
7. 48 kHz 混合 PCM 采样数等于真实母带 `S`；旁白无截断；最终只有一视频、一音频，H.264 和 AAC 解码及音画同步校验通过。
8. 仅修改音效应命中无声视觉缓存，修改文字应重建视觉但复用原始音效素材；过期人工预览和正式画质收据被现有门禁拒绝。
9. 技术样片与真实素材审批完全隔离；真实镜头效果的美感、字幕替代误解、音效听感和画面主体必须由真人审核。

### 11.2 必测反例

| 分类 | 反例 | 预期 |
| --- | --- | --- |
| 视觉 | 主体占中、已有大面积文字、强烈运镜、画面无安全区、长词超宽 | 跳过或人工待审，给出采样帧/候选位置证据 |
| 语义 | 低信息词重复、情绪克制镜头、人工跳过、用户固定爆字 | 跳过决策优先、固定项冲突报告 |
| 文本/语音 | 相同词两次、`300%`、缺声学字符、声音截断、跨镜头短词 | 原文范围正确，未知声学不伪造时间 |
| 动画 | 第一帧、峰值帧、停留、最后一帧、转场左右边界、弹性超调 | 精确帧验证、无重复/闪烁/边界越界 |
| 高级效果 | 粒子数超预算、透明解码失败、字体缺字、特效文件哈希变化 | 降级有原因并重新审核，非法资产拒绝 |
| 音效 | 负采样偏移、超出母带、未授权、强冲击音过量、重复叠加 | 自动拒绝/待审；不污染原母带 |
| 混音 | 原生 44.1 kHz/单声道 SFX、输入浮点异常、静音计划、AAC 延迟 | 规范化重采样或错误，PCM 时长固定且听感可审 |
| 缓存 | 改音效后视觉缓存 miss、只改字体却沿用旧视频、旧批准继续使用 | 明确失败并修复依赖关系 |
| 旧项目 | 缺省所有新文件、只启用视觉、只启用音效、显式双关闭 | 各模式可运行且不强制多余素材 |

### 11.3 技术样片和人工验收

提供至少 60 秒的技术样片，覆盖 3 类视觉布局、`skip` 镜头、六类一级动效、两类二级动效、四类音效（不一定全部同时播放）、真正静音镜头、两种以上转场，并提供入场/峰值/退出/转场抽帧、全片声音报告、源资产哈希、缓存记录与 FFprobe 验证。技术夹具真实执行才可标 `PASS`。

正式生产样片只能在真实图片来源、许可、逐图审图、真实配音及用户批准齐备时执行；不足时应明确 `NOT_RUN`，不能伪造真人批准或以合成测试收据替代。

## 12. 实施阶段与推荐顺序

- **SC-K1：** 数据契约、可选开关、字体与音效素材入库、旧工程兼容。
- **SC-K2：** 视觉理解、可跳过判定、声学映射、布局与文字/音效事件编译。

- **SC-K4：** 全片音效选择、素材验证、FFmpeg 样本级混音、双母带验证与独立缓存。
- **SC-K5：** 端到端有声预览、人工审批、实际视频/音画测试、性能与回归证据。

详见配套 Codex 实施清单。每阶段都应提交可运行命令、有效/反例测试、真实执行输出与 `PASS / FAIL / NOT_RUN / UNAVAILABLE`，而不是把文本设计当成已经完成的功能。
