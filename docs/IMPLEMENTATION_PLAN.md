# Layered Motion Video 分阶段实施计划与验收清单

> 版本：0.1.0（开发实施蓝图）  
> 配套设计：[DESIGN.md](../DESIGN.md)  
> 实施对象：固定原创角色 + 单人口播 + 分层插画 + Remotion 关键帧动画的视频 Skill  
> 当前仓库阶段：方案与规范设计

## 1. 交付策略

按照“先用一个主画面验证分层动画 → 再扩展整段视频 → 最后接入 Agent 自动生产”的顺序开发。

每个阶段形成可运行、可视化、可重复的交付物。下一阶段依赖上一阶段的验收结果。首版技术主体为 Python 流程管理、JSON Schema 数据协议、Remotion 逐帧动画和 FFmpeg 媒体处理；图片可以由 Agent 调用外部生图工具或用户手动提供。

角色库的第一个候选包为 `guaili-town`：阿团、狐九、乌点、阿砾以及辅助叮盒。角色的正式视觉身份需要用户审核标准设定图后固化。所有开发任务均应使用 `character_id` 与 `asset_id` 引用，避免硬编码角色名称和职业。

## 2. 优先级总表

| 阶段 | 交付重点 | 可验证结果 | 前置条件 |
| --- | --- | --- | --- |
| P0 | 仓库、协议与工程框架 | 最小 CLI、项目隔离、Schema 校验 | 设计基线 |
| P1 | 角色库、场景库与静态合成 | 复用素材生成 1 个完整主画面 | P0 |
| P2 | 动画引擎与信息组件 | 人物、道具、气泡、文字、数字全部可按帧运动 | P1 |
| P3 | 语音对齐、工作流与审核 | 带旁白的 12 秒动态镜头及完整审核收据 | P2 |
| P4 | Agent 规划与素材生成适配 | 文案→分镜→资产计划→动画配置 | P3 |
| P5 | 90 秒首期样片 | 七个主画面、完整旁白、审核和可复现重渲染 | P4 |
| P6 | 泛知识生产复测 | 更换三个知识主题，验证演员与动作库复用 | P5 |

## 3. P0：基础框架和规范

### 工作清单

- [ ] 建立 `SKILL.md`，明确触发条件、制作步骤、人工审核边界。
- [ ] 创建 Python 包 `layered_motion_video/` 和统一 CLI 入口。
- [ ] 建立 `schemas/` 的 `world`、`character`、`asset`、`scene`、`motion`、`project` 六类 JSON Schema。
- [ ] 建立数据版本字段和升级校验策略。
- [ ] 实现项目创建、清单写入、路径限制、原子保存和项目锁。
- [ ] 建立 `content/<project>/` 项目目录，默认忽略生产内容的 Git 跟踪。
- [ ] CLI 支持 `doctor`、`project init`、`project status`、`schema validate`。
- [ ] 统一日志输出：机器可读 JSON、错误码、操作对象、收据和诊断位置。
- [ ] 锁定 Python/Node/Remotion/FFmpeg 的实际版本，记录可复现安装命令。
- [ ] 对仓库原许可证、生成资产授权和第三方依赖建立独立记录。

### 验收

1. 能从一份实际口播文案创建独立项目，原始文案字节保留。
2. 任何不合法的路径、对象引用、数据类型、帧范围都会有明确错误。
3. 能用 Schema 正向验证有效实例、反向拒绝未知动作与无效素材路径。
4. 重新执行 `init` 不覆盖现有项目。
5. 单元测试覆盖目录边界、原子保存、锁竞争、哈希校验和 Schema 版本。

## 4. P1：公共世界资产与静态画面

### 工作清单

- [ ] 实现 `worlds/guaili-town/` 候选资产清单与版本信息。
- [ ] 建立演员基础设定、姿势、表情、视角与锚点数据结构。
- [ ] 建立七种背景场景的元信息格式及前中后景图层协议。
- [ ] 支持角色/场景/道具按 ID 查询，优先从现有资产库复用。
- [ ] 支持项目快照：复制或锁定已批准素材，并记录摘要、许可证及生图来源。
- [ ] 实现 PNG Alpha、画布尺寸、主体外接框、锚点合法性检查。
- [ ] 支持场景层级 `z_index`、位置、缩放、裁切与字幕安全区。
- [ ] 输出每个主画面的静态效果 PNG 和合成清单。
- [ ] 建立素材来源、参考图、提示词及人工视觉审核记录。

### 验收

1. 一个主画面至少包含背景、人物、可交互道具和前景遮挡图层。
2. 相同演员引用多张姿势图片时，画布锚点和地面位置稳定。
3. 前景柜台正确遮挡角色身体，背景不出现重复烘焙的人物。
4. 素材缺失或图片不具备透明通道时可定位到具体 `asset_id`。
5. 重新渲染相同配置可稳定还原构图，并能证明所用资产版本一致。

## 5. P2：Remotion 分层动画组件

### 组件任务

- [ ] 进入/退出、平移、旋转、缩放、透明度、漂浮和轻量摇摆。
- [ ] 角色姿势与表情贴图替换，保持底部和面部锚点。
- [ ] 道具沿路径移动、出现、计数复制，支持可配置前后遮挡。
- [ ] 气泡：对白式、思考式、注释式；自动连接角色锚点。
- [ ] 中文文字：淡入、逐字、逐行、关键词强调与自动换行。
- [ ] 数字：金额/整数增减、千分位与单位格式化。
- [ ] 图解：箭头生长、简单柱形比较、数据标记。
- [ ] 强调：盖章、弹性入场、轻晃、脉冲。
- [ ] 镜头：构图整体平移、推近、拉远。
- [ ] 动画曲线和时钟保持每帧确定性，所有效果由相同的帧索引驱动。
- [ ] 内建动作注册表，`motion.json` 只选择已注册动作及参数。

### 动画测试用例

| 用例 | 验证点 |
| --- | --- |
| A1 人物平移 | 从两个坐标之间移动，起止位置与速度曲线正确 |
| A2 姿势替换 | 从站立变成指向，锚点位置稳定 |
| A3 商品入车 | 物体沿路径到达购物车，遮挡层级正确 |
| A4 思考气泡 | 尾部跟随角色挂点，文字在气泡内正确断行 |
| A5 动态账单 | 216 → 减 50 → 166，数字与文字清楚可读 |
| A6 镜头推近 | 画面主体聚焦正确，字幕留白不被裁切 |
| A7 多效果并行 | 同一帧运行不同对象动画并保持稳定 |
| A8 数据校验 | 未声明对象、未知动作、帧越界、互斥冲突均被拒绝 |

### 验收

交付可独立播放的 12 秒分层动画样片（可先使用批准的测试资产）以及对应的 `scene.json`、`motion.json`、渲染命令、单元测试和关键帧截图。

要求至少实现：人物平移、姿势替换、金币/商品移动、气泡文字与数字变化。打开同一输入两次渲染时，可重复得到同样的有效场景状态。

## 6. P3：配音、语义时间锚点与审核工作流

### 工作清单

- [ ] 支持导入用户旁白 WAV/MP3，规范化输出和有效时长检测。
- [ ] 提供可配置本地 TTS/外部提供者接口；生成旁白记录参数、来源和试听文件。
- [ ] 对用户导入音频进行内容核对；对生成配音设立真实试听审核。
- [ ] 接入中文词/短语对齐，并生成 `cue_id` → `start_frame/end_frame` 映射。
- [ ] 对重名短语、缺失短语、低置信度匹配提供纠正入口。
- [ ] 分镜、素材/静态效果、生成配音、完整动态预览分别设置审核记录。
- [ ] 审核绑定内容摘要：已经修改的产物必须重新审核受影响阶段。
- [ ] 实现项目级 `status`、`resume`、`revise`。
- [ ] 实现预览镜头合成、全片合成、字幕安全校验和媒体解码检查。
- [ ] 所有合成视频以实际音频时基确定镜头长度与字幕时间。

### 验收

1. 音频与画面时间码换算可重复且对齐锚点有效。
2. 删除一个必需对齐锚点会阻止该镜头正式执行，并给出定位诊断。
3. 修改一个动作会只重建相关镜头与全片预览。
4. 生成新旁白会使受影响的语音时间轴、预览审核失效。
5. `resume` 不会代替用户确认任何需要审核的版本。
6. 输出 12 秒带旁白、字幕、完整关键帧截图与质量报告的样片。

## 7. P4：Agent 自动规划与素材供应

### 工作清单

- [ ] 从用户已提供/已审核的口播文案解析叙事段落和知识逻辑。
- [ ] 生成主画面、可动画对象、视觉事件、镜头构图和字幕安全区。
- [ ] 整段文案覆盖校验，阻止重复、漏句、擅自修改已审核文案。
- [ ] 对演员角色进行语义选用与职业设定，但角色引用始终为固定 `character_id`。
- [ ] 优先检索现有角色/场景/道具，输出复用清单和缺失清单。
- [ ] 生成针对缺失姿势、表情、场景、道具的中文素材提示词。
- [ ] 支持“Agent 生图”和“用户手动供图”两种工作路径。
- [ ] 对 AI 生成的图片执行技术检查，并要求实际视觉审核。
- [ ] 将视觉事件关联旁白语义锚点，生成可验证的 `motion.json`。
- [ ] 生成对应静态构图效果图，供用户批准后进入完整动画预览。
- [ ] Agent 主要执行计划生成、候选选择和视觉质量判断，渲染执行保持确定性。

### 验收

对同一段真实文案进行至少两轮从分镜到动画的重新规划，检验：
- 主画面持续性与事件覆盖。
- 角色一致性与公共素材复用。
- 新素材数量和变更对缓存的影响。
- 叙事动作是否与对应旁白语义相符。
- 所有 JSON 能通过 Schema 与资源引用校验。

## 8. P5：完整 90 秒基准样片

### 选题

《阿团去超市买28元的东西，最后为什么花了166元？》

### 七个主画面

1. 住宅：购物目标与预算 28 元。
2. 超市入口：满 200 减 50 促销。
3. 货架：增加 89 元小夜灯和 99 元猫窝。
4. 收银台：216 元总价、50 元优惠、166 元实付。
5. 图解舞台：原计划 28 元与实际 166 元，额外支出 138 元。
6. 条件对比：真正有需求与额外被诱导消费的不同结果。
7. 超市出口：发现新的满减活动，形成轻度讽刺式反转。

### 预期交付

- 一份完整中文旁白，单一配音音轨。
- 分镜 JSON 和完整画面方案。
- 原创演员标准参考图及此期使用的透明姿势贴图。
- 背景、道具、静态主画面预览图。
- 各主画面 `motion.json` 与真实语音对齐数据。
- 1920×1080、30fps 的完整 MP4。
- 关键帧、缓存收据、素材清单与质量报告。

### 验收维度

| 维度 | 判定方式 |
| --- | --- |
| 完整性 | 原文全部由旁白覆盖，故事因果顺畅，七个主画面都有有效构图 |
| 正确性 | 28 + 89 + 99 = 216；216 - 50 = 166；166 - 28 = 138 |
| 一致性 | 阿团在不同场景仍是同一原创角色 |
| 动画性 | 至少包含角色动作、道具路径、气泡、文字、数字及镜头动作 |
| 时序 | 所有动作对应有效语音锚点；无非法帧事件 |
| 视觉质量 | 背景与人物图层协调，主体、数据和字幕不遮挡 |
| 工程可复现 | 能从锁定的内容目录和配置完成重渲染 |
| 审核 | 分镜、静态画面、新生成配音、全片预览按需获得真实批准 |
| 技术质量 | 全片可解码，时长、帧率、分辨率及音视频轨满足要求 |

若样片中某个阶段失败，保留已完成的中间资产和诊断数据，先修复失败阶段，再恢复后续渲染。

## 9. P6：泛知识生产复测

首期制作完成后，以相同演员和公共资产库另做三个不同主题的短样片：

| 类型 | 样片主题 | 需要验证的资源变化 |
| --- | --- | --- |
| 日常科学 | 冰箱开着门为什么不能给整间屋子降温？ | 工坊背景、温度示意和物理流程动画 |
| 职场认知 | 会议开得越多，为什么工作反而可能更慢？ | 办公室背景、任务卡、流程图 |
| 生活心理 | 明知道应该睡觉，为什么还会忍不住刷手机？ | 住宅背景、手机、时间与情绪图解 |

重点统计每条视频新增演员姿势、道具和场景数量、公共素材复用率、人工修正次数、每主画面渲染耗时及总时长。此时再评估是否需要引入 Manim、骨骼动作或可视化编辑器。

## 10. 测试矩阵与回归保障

### 单元测试

- 项目路径越界、符号链接、防覆盖、原子存储、锁冲突。
- Schema 校验：类型、缺失字段、未知动作、循环引用、帧越界。
- 角色锚点、坐标换算、层级和图层裁切。
- 插值函数、姿势替换、相同对象互斥动作检测。
- 时间锚点匹配、重复中文短语和音频对齐边界。

### 集成测试

- 角色素材 → 静态构图 PNG。
- 场景配置 + 动画配置 → Remotion 镜头 MP4。
- 音频对齐 + 动作配置 → 声画同步镜头。
- 多主画面 → 全片合成 → 字幕 → FFprobe/FFmpeg 完整解码。
- 修改一个 `motion.json` 后的局部重渲染。
- 修改一个共享角色资产后引用镜头的依赖失效。
- 审核收据校验与用户批准版本绑定。

### 视觉验收

抽样查看开始、事件发生前后、镜头结尾以及语义反转的关键帧。检测透明边缘、贴图跳动、视觉遮挡、文字排版、信息节奏、字体兼容和重要数据可读性。

将可量化检查和主观审美检查记录在不同字段中；对无法自动判定的观感设置 `REQUIRES_REVIEW` 状态。

## 11. 首版需要优先规避的工程风险

| 风险 | 防范与测试策略 |
| --- | --- |
| 角色跨镜头变脸 | 标准参考图、身份清单、资产审批和版本锁定 |
| 主体和背景重复 | 图片生成阶段隔离前景角色，布局前做重叠检查 |
| 图层移动后留下空洞 | 独立背景、遮挡补全或重新生成对应背景 |
| 聊天气泡挡住角色/字幕 | 绑定锚点、安全区与碰撞诊断；允许人工调整 |
| 字体显示差异 | 固定项目字体配置、发布授权核验和跨平台抽帧 |
| 动作看起来机械重复 | 多种缓动模板、语义动作选择和视觉节奏审核 |
| 长时间同一画面停滞 | 检测连续约 6 秒无有效变化的片段并给出复核提示 |
| 时间轴与口播失配 | 真实音频对齐、语义锚点和独立人工纠正 |
| 生图成本失控 | 公共资产优先、缺失才生成、素材缓存与增量恢复 |
| 第三方版权风险 | 原创角色，记录来源、许可证及使用范围 |
| 智能体输出任意代码 | 只读取 Schema 合法的声明式动作配置 |
| 自动化验收过度自信 | 自动技术报告与用户视觉/听觉验收分开 |

## 12. Codex 工程实施约束

进入编码阶段时，Codex 应以本方案为需求基线，先检查已有文件与 Git 状态，再按 P0→P6 的阶段目标实施。

执行规范：

1. 先给出本阶段修改清单及可验收的输出。
2. 使用新增模块和独立接口组织代码，稳定对外协议。
3. 每次阶段性改动同时提交验证用例与实际运行记录。
4. 将测试数据与生成结果保存在 `content/` 中，避免污染源码目录。
5. 明确报告 `PASS / FAIL / NOT_RUN / UNAVAILABLE`，拒绝以猜测替代运行结果。
6. 资产无法生成时允许使用标明来源的测试夹具验证渲染功能，真实素材一致性则另行审核。
7. 运行前确认当前变更状态，保留已有用户修改。
8. 仅进行当前阶段范围内的实现、构建与验证；提交、推送、发布由用户另行授权。
9. 阶段验收记录应包含命令、工具版本、产物路径、错误/警告及后续阻碍。
10. 以 12 秒动效样片和 90 秒完整样片的真实视频为端到端证据，不以静态截图或模拟成功代替。

## 13. 阶段验收记录格式

建议各阶段保存 `reports/milestone-PN.json`，至少包含：

```json
{
  "milestone": "P2",
  "status": "NOT_RUN",
  "environment": {
    "python": null,
    "node": null,
    "remotion": null,
    "ffmpeg": null
  },
  "inputs": [],
  "outputs": [],
  "tests": [],
  "human_review": "PENDING",
  "blocking_issues": [],
  "notes": ""
}
```

状态只有实际运行后才能更新。每个阶段的产物能被下一个阶段消费，才算形成有效交付。
