# 封面工坊 Fabric.js 架构与迭代计划

更新日期：2026-10-21

## 1. 当前架构

- Fabric.js 7.4：文字、图片、图层交互、预览和高清 PNG 导出。
- Flask：字体索引与字体文件服务、设计与素材读写、版本冲突校验。
- 场景模型 v2：文案、字体、背景、图层元数据和画幅布局变体的统一数据契约。
- Pillow：经典封面编辑入口和历史模板的视觉回归基准。
- Playwright-core：使用本机 Edge 运行浏览器级渲染验证，未来可用于自动化封面生成。

### 本轮已经实现

1. 经典模板通过 GET /api/designs/legacy 导入为 v2 场景草稿。
2. 场景文档独立保存到 data/designs/，支持创建、复制、更新、列出和重新打开。
3. 设计修订号避免同一进程内多个窗口的陈旧数据覆盖。
4. 背景与头像采用内容指纹保存；经典版素材首次保存新设计时生成独立快照。
5. 六种比例使用独立的布局配置和位置覆盖：自动定位随文字变化重新排版，手动定位按画幅保存。
6. 小标题和分隔线作为一个组合对象，账号和头像按比例安全位置计算。
7. 字体和素材通过受控本机路径访问，浏览器端加载后可在无 Python 图片渲染请求的情况下修改与导出。
8. 验证环境独立于真实 data/，确保测试保存设计和上传图片不会覆盖日常模板。

## 2. 统一场景模型

Python：canvas_config.py、scene_models.py、scene_store.py。

JavaScript：fabric-poc/src/scene-model.mjs、fabric-poc/src/ratio-layout.mjs。

示例结构（字体 ID 为示意占位符）：

  },

  },

    "darkness": 78,

    "glow": true
  },
  "activeRatio": "3:4",
  "variants": {
    "3:4": {
      "title": {"mode": "auto", "x": null, "y": null},
      "subtitle": {"mode": "auto", "x": null, "y": null},
      "account": {"mode": "manual", "x": 20, "y": 55}
    },

      "title": {"mode": "auto", "x": null, "y": null},

其中 layers 示例省略了具体属性；实际 API 会补齐字体、内容引用与分组定义。画幅尺寸由 Python canvas_config.SIZES 与前端 RATIO_DIMENSIONS 分别定义，并通过测试保持一致。场景文档只保存用户可编辑状态，不在 JSON 中保存浏览器私有的 Fabric 对象或 Base64 图像。

字体引用继续采用现有索引 ID，后续可增补文件哈希与更稳健的字体替换检测。图层模型当前固定基础五层，自由添加图层需要新的模型版本与交互能力。

上述基准中的 Python 与 Fabric 中心坐标偏差受两种因素影响：字形度量不同，以及已经有意采用的画幅专用自动布局不同。因此跨渲染器的像素中心差不是浏览器预览与 PNG 导出的一致性指标。

浏览器版的同一画布预览与导出为权威结果；历史模板采用明确的设计版本及迁移预览，由使用者对外观变化进行确认。

## 4. 后续任务

### 专业图层编辑进展

已完成三块文字的锁定与解锁，五个基础图层的显隐和层级顺序调整，以及实时辅助线与智能吸附。背景固定为最底层，头像仍采用各画幅默认位置。辅助线只显示在编辑界面，PNG 由 Fabric.js 直接导出。

场景 v2 现在持久化 `layers[].visible`、`layers[].locked` 和 `layers[].zIndex`，保留旧模板的默认属性兼容。操作历史覆盖图层调整和鼠标拖动；拖动后刷新边界缓存再计算中心、边缘、安全边距的吸附。参考线与坐标测试包含真实鼠标操作、保存重开、撤销重做及显隐后的导出差异。

现阶段已提供自由图层、组合与跨画幅独立几何；后续重点是复杂组合变形、专业画布视口控制与比例专用样式覆盖。

### 文本与图像属性面板进展

属性面板已覆盖三块文字、圆形头像与背景。文字支持自动/固定字号、字距、行距、颜色、不透明度、描边、阴影与旋转；头像支持不透明度、角度和缩放；背景支持压暗、裁切重心与光晕。这些属性均由浏览器完成实时预览及原生像素 PNG 导出。

- Python 场景模型 v2 使用 `layers[].style` 保存文字和头像样式，对数值范围、颜色及阴影结构执行校验；旧场景数据采用默认样式补全。
- 浏览器端 `style-state.mjs` 负责样式状态校验，`main.js` 使用 FabricText、Group、Shadow 等对象渲染对应效果。
- 字号设为自动时仍保留长标题均衡换行策略。固定字号按原始画布像素执行校验，不会偷偷缩小用户的指定值。
- 小标题与分隔线保持组合状态；整体旋转与透明度作用于组合对象。
- 文字旋转通过最终轴对齐边界执行约束；浏览器拖拽完成后的旋转/缩放操作同步为场景属性。
- 设计重新打开可恢复属性，撤销重做能够恢复场景样式；浏览器端 PNG 视觉一致性纳入回归测试。

属性现阶段属于**同一设计的全局样式**，而各画幅独立保存的是图层位置。后续视用户需求决定是否为各画幅增加独立样式覆盖、更多图形元素及组合操作。

### 可扩展图层与组合能力

为了保持原有场景 v2 和五个基础图层的兼容性，新增独立的 `extras` 数据集合：

- `extras.layers` 为自由文字、图片、矩形、椭圆保留稳定 ID、百分比几何、样式、层级与素材引用；
- `extras.groups` 记录组 ID、成员引用、显隐和锁定。组内成员继续保存画布绝对百分比坐标，不嵌入 Fabric 的私有序列化结构；
- 浏览器使用声明式记录实例化 Fabric.Textbox、Fabric.Rect、Fabric.Ellipse、Fabric.Group。组合整体拖动结束后，更新每个成员坐标，并重新生成组对象；
- 后端限制扩展图层数量、成员引用与图片素材指纹，检查文件存在性。旧设计缺少 `extras` 时默认解析为空集合；
- 操作历史覆盖添加、删除、组合/解组、图层变换。通过自动化浏览器验证组合真实鼠标移动、设计重开后 PNG 一致以及素材入库。

分阶段边界：当前组合支持整体移动和单画幅独立定位；组内非平移变形、多组嵌套及更复杂的矢量形状属于后续阶段。

### P1：专业图层编辑与命令历史

目标：把目前的 Fabric 原型完善为稳定的高频封面编辑器。

实施顺序：

1. 把 fabric-poc/src/main.js 拆分为渲染、场景仓库、字体资产、布局、图层交互和导出模块。
2. 增加专业图层面板：对象选择、显隐、锁定、顺序、组合与解组。
3. 加入可视化参考线、中心线和元素边缘吸附；吸附阈值基于视口缩放换算。
4. 实现编辑命令历史。拖动中的多个指针移动事件合并为一次撤销操作；属性修改也支持撤销重做。
5. 扩展可编辑样式：字号、字距、行距、颜色、描边、阴影；所有新属性必须支持保存后重新打开。
6. 建立更完整的浏览器视觉回归用例，覆盖鼠标、键盘、字体切换、各比例导出和撤销重做。

验收：生产页面所有操作由浏览器即时响应；持久化后无图层状态丢失；PNG 与网页画布的层次及视觉效果一致；已有场景 v2 可以按迁移规则继续使用。

### 自由图层多画幅布局进展

自由图层在共享 `frame` 基础上，使用 `ratioFrames` 记录画幅专用几何。当前实现覆盖全部六种比例：3:4、9:16、16:9、4:3、4:5、1:1。

- **画幅继承**：没有单独设置时，从原有 `frame` 读取相对位置、尺寸和旋转角度；旧场景由服务端填充空的画幅覆盖集合。
- **局部修改**：在画幅中直接拖动、缩放、旋转或编辑数值时，只写入当前 `ratioFrames[ratio]`。组移动对当前画幅的所有成员生成覆盖，不修改共享基线。
- **布局恢复**：当前比例可恢复继承；也可将当前比例布局设为共享基线，统一所有比例。两种操作都进入撤销重做。
- **自由文字缩放**：纵向缩放使用可选 `scaleY` 记录于当前比例的图层几何中，字体基础字号与颜色依然为共用样式。
- **校验**：Python 验证比例名称、坐标范围、大小、角度、文字缩放、图层身份和组合成员关系；浏览器重绘时以最新构建序号过滤异步过期结果。
- **验收**：3:4 与 16:9 可保存不同几何，9:16 继续继承；图层调整、组合拖动、恢复继承与统一操作均通过撤销重做；保存重开后不同画幅的 PNG 保持一致。

后续针对特殊平台的安全区域、对象自动避让和组合的非平移变形，继续在 P2 中建设。

### 画幅安全区与质量诊断进展（2026-10-21）

已完成浏览器画布安全区和质量检查能力：

- `layout-diagnostics.mjs` 提供按画幅配置的参考安全边距及界面遮挡区域，检测实际可见图层越界、重要内容安全区、显著文字遮挡、低透明度、低字号和背景对比度。
- 编辑器叠加画布 `guide-overlay` 绘制可开关的安全区与参考遮挡范围，PNG 只从 Fabric.js 主画布导出。平台坐标明确标注为经验预设。
- `quality-state.mjs` 记录画幅独立的安全区方案与人工允许重叠关系。历史全画幅确认关系兼容，支持撤销，删除或解组时清除失效图层引用。
- `quality_models.py` 对画幅兼容性、前景图层引用和确认规则数量进行保存校验。
- `font_coverage.py` 及 `POST /api/fabric-poc/font-coverage` 仅在用户预检或导出时读取白名单字体字符表，日常编辑无需服务端图片渲染。
- 可导出机器可读 JSON 诊断报告；缺字与画布越界属于错误并阻止网页 PNG 下载，普通安全留白和遮挡提示允许人工确认。
- Python、JavaScript 和浏览器回归已覆盖安全区叠加与导出隔离、缺字、重叠允许和撤销、跨画幅独立与设计保存重开。

界面安全区及背景采样对比度是经验规则，不能替代真实设备和实际平台的人工审核。当前报告针对活动画幅；后续可以执行六种画幅的批量扫描，并整合到批量导出任务。
### P2：更广泛的版式约束与布局诊断

- 为不同平台与设备增加可调整的参考安全区与界面遮挡覆盖规则。
- 加入自定义重叠许可规则、字号下限、缺字、对比度和比例专用预设。
- 支持手动固定的位置与自动流式布局关系混用。
- 扩充 100 组以上的长短中文标题，并提供机器可读的布局诊断清单。

验收：批量预览时明确区分需要用户确认的人工布局和可以自动导出的标准布局。

### P3：批量生成与任务管理

- Python 后台通过固定版本的无头 Chromium 调用同一 Fabric.js 模块。
- 任务读取模板快照、字体 ID、图片哈希和输入文案。
- 浏览器实例复用并控制并发，等待字体就绪后导出。
- 支持失败重试、导出清单与和视频内容目录的关联。
- 设计库提供可按比例过滤的预览缩略图、复制及版本管理。

验收：100 条文案可复现批量渲染，失败任务有明确原因和独立重试能力。

### P4：正式产品入口

2026-10-21 已将 Fabric.js 可视化编辑器设为默认首页 `/`，经典 Pillow 编辑器通过 `/legacy` 独立使用。旧 `/fabric-poc` 浏览器书签会跳转到正式首页。

`editor_build.py` 在 Python 正式启动时检测前端资源，按需执行 npm 依赖安装与打包；构建产物保留在本机。正式编辑器读取 `data/designs/`，经典默认模板继续使用 `data/preset.json`。两种入口的网页、渲染和数据写入路径互相隔离。

后续生产化工作继续推进批量任务、编辑模块拆分以及更多真实封面的视觉验收。默认路由切换本身不会改变这些工作的验收范围。

## 5. 已提供的后端接口

| 请求 | 用途 |
|---|---|
| GET /api/designs/legacy | 导入经典参数为场景草稿 |
| GET /api/designs | 列出设计库 |
| POST /api/designs | 创建独立设计 |
| GET /api/designs/{id} | 读取设计 |
| PUT /api/designs/{id} | 保存带修订号的设计 |
| POST /api/designs/assets | 素材入库 |
| GET /api/designs/assets/{id} | 读取素材 |
| GET /api/fonts | 读取系统与项目字体目录 |
| GET /api/fabric-poc/font?id= | 读取受限的本机字体 |
| GET /api/fabric-poc/asset/{kind} | 读取经典模板的已有图片 |

服务只监听 127.0.0.1。设计和素材都保存在本机，使用模板模型校验和路径白名单。资源读取接口目前保留既有路径，以维持浏览器编辑器和自动化检查的兼容性。
